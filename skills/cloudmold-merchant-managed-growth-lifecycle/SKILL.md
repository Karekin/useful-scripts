# 托管商家入驻与成材全生命周期

本 Skill 管理“服务托管业务新商入驻与商家成材”的业务规则、人工审核和证据门槛。它不同于 `cloudmold-merchant-experience-rectification`：后者只处理既已判定商家责任后的消费者体验整改；两条流程相互独立，不能用成长考核替代消费者整改，也不能用整改结论升级、降级或清退商家。

执行前读取同目录 `skill-task.json`。当前 SkillTask 已对接 Merchant red-zone 中**已落地**的托管准入后端 happy path：在既有入驻申请审批完成后，可依次执行托管准入建档、邀请/来源归因、证据包提交、仅供人工采纳的 AI 货盘诊断建议、人工接受 AI 建议、验厂任务创建/认领/预约/执行/一审/终审、验厂完成以及人工准入终审结论落库，并在最后通过已注册的 Merchant managed-admission workflow query 只读回查终态。所有写入仍是 R3 审批、幂等键、版本校验和外部证据引用约束下的显式操作；AI 不得替代人工审批或直接改变准入结论。

首期仍**不**自动生成邀请码或入驻链接、不自动派单或分配买手、不自动变更商家等级或权益、不变更店铺，且不自动执行清退。邀请码使用、买手分配、等级/权益决定、试用/成长期评分和托管池退出现已具有受控 Merchant 命令与统一只读回读，但它们属于需要人工选择的分支决定，尚未注册为当前 SkillTask 可轮询的专用能力；因此本 Skill 要求人工以 R3 审批、配置版本和证据引用显式发起，不能冒充为自动完成。

当前 SkillTask 只覆盖“**AI 建议已被人工接受且进入验厂链路**”的受控直行路径。终态只读回查目前仅覆盖 Merchant managed-admission workflow 已公开的 `SUCCEEDED/FAILED` 结果，不扩展为 invitation/inspection/buyer-assignment/entitlement/exit 的独立自动轮询。若人工驳回 AI 建议、建议直接终审而非验厂、验厂进入整改/取消分支、或后续需要买手分配、等级权益变更、试用/月度评分或清退判断，必须由人工基于现有证据重新发起相应受控动作；不能伪装成同一条自动化主路径已经闭环。

## 0. 受控人工审核与证据门槛

每次入驻、试用期、月度成长期或清退复核都必须建立一份不可混用的商家生命周期证据包，并关联规范商家引用（尚未创建规范商家时，关联申请和邀请码引用）。证据包至少包含：

- 邀请码/入驻链接、创建人、招商人员、来源归因和申请人提交材料；
- 货盘诊断结论、人工复核结论、买手 TL 确认和店铺/买手分配记录；
- 验厂任务引用、状态历史、验厂小二认领/执行记录、预约、现场或远程证据、复验和审核人；
- 验厂、复检、资质、档案、发品质检、商品/大仓质检、经营和供应链的来源记录及审核人；
- 每项义务的观察期间、计算口径、评分、整改期限、复核结论和最终决策；
- 等级/权益调整或清退所依据的规则版本、人工审批和通知证据。

招商中台人工复核、买手 TL 最终风格确认、验厂小二认领与执行、QA 验厂/审核结论、等级/权益决策和清退决定均由有权人员在相应权威系统或受控人工流程中作出。缺少任何必需证据、审核人或结论时，行动单必须保持未解决；Agent 只能提出待审清单，不能补造通过结论。

## 1. 新商入驻六阶段

1. 招商小二创建**唯一**邀请码或入驻链接，并绑定招商人员和来源归因。链接/邀请码的唯一性、有效期和使用记录必须可审计。
2. 商家提交品类风格、供给模式、多渠道经营表现及货盘资料。
3. Agent 仅对机审通过的申请做货盘诊断，输出商品/款式结构和价格带的诊断建议及证据索引；它不把建议写成准入结论。
4. 诊断不通过的申请转招商中台人工复核，人工结论只能是：**人工通过**、**补齐信息**、**不可流转**或**转买手 TL**。
5. 买手 TL 最终确认风格，并人工分配自营或托管大店及对接买手。
6. 根据经营数据、货盘评估和供应链能力，人工初始化商家等级与基础权益，并记录依据和审批人。

通用 KYC、合同、规范商家/店铺激活仍由商家经营域的入驻阶段 `cloudmold-merchant-onboarding-lifecycle` 负责。本 Skill 只在它的权威事实和上述人工证据齐备后接续托管成长判断，不能绕过该准入门禁。

## 2. 入驻后的受控验厂流程

商家完成规范入驻后，业务规则要求创建一条受控验厂任务，并交由验厂小二认领和执行。首期后端提供受审批保护的任务创建、认领和状态流转命令；创建人、认领人、预约和每次状态变更都必须保留操作人和外部证据引用。它不是后台自动派单：没有经批准的显式命令和认领人证据时，Agent 不得声称已创建、分配或完成验厂。

验厂任务状态机为：**待认领 → 待预约验厂 → 待验厂 → 待 QA 验厂 → 待整改 → 待一审 → 待终审 → 验厂完成**。除 `验厂完成` 外，任一非终态均可取消；取消后进入终态 `已取消`，必须保留取消人、原因和当时证据快照。一般问题的整改和复验应沿 `待整改 → 待一审 → 待终审` 流转，不得跳过审核。

验厂完成必须将综合评分、以下五项分项评分、问题清单、逐项整改要求及其证据写入受限外部证据包，并把不可篡改的证据引用随验厂状态流转和回读保存；首期不把原始资料或评分明细复制进商家业务库：

1. **商品开发**：设计师、版房和开发能力。
2. **视觉素材**：摄影、美工和 AI 做图能力。
3. **生产及供应链**：组织负责人；订单/外发与生产计划；现场工序与标识清洁；厂仓条件；控货履约及改进响应。
4. **质量管理**：质量组织、产前准备、成品检验与记录、现场产品质量。
5. **仓储物流**：数字化仓储、现场流程和职责、快递时效。

高风险或硬性不通过项必须直接阻断通过或进入整改/复验，不能被综合评分掩盖。一般问题可以走整改与复验，但复验结论、证据和审核人必须独立于原始检查记录，并在终审前保持可追溯。

## 3. 试用期：三项义务与全通过门槛

试用期只有以下三项义务均通过，商家才获得成长入池资格、基础上新权、基础经营看板和基础坑位：

1. **验厂与质检配合**：按要求验厂、整改和复检；材料真实；验厂等级为 **C 级及以上**。
2. **商家档案完整**：主体、类型、供应链、版房和资质完整，且真实可验证。
3. **基础发品质检**：标题、SKU 价格和尺码合规；劣质图比例 **<10%**；尺码覆盖度 **>80%**。

任何一项不通过即进入限期整改，不能以其他项目抵消。到期仍未通过或整改无效时，按清退规则提交人工清退复核；在最终决定前不得自动授予成长权益。

## 4. 成长期：月度九项义务、评分与权益

每项义务每月都必须形成可追溯的观察周期、来源证据、人工审核结论和评分。达标阈值由商家等级、类目和企划等级等规则配置决定；除明确的 S/A 企划匹配口径外，不在本 Skill 中伪造固定数值。九项评分进入综合能力评分，决定商家的**等级跃迁**（升级、维持或降级）；权益只在当月对应义务持续满足时生效。部分不达标可以降级或减坑位，红线、严重违规或多次整改无效可以直接进入清退判断，不能被综合评分掩盖。当前评分、权益和清退后端尚未落地时，上述判断必须由人工审核及证据门槛执行，不得由 Agent 自动写入。

### 4.1 无货源风险控制

- **义务项**：控制无货源、虚假供给和异常转单风险。
- **考核内容**：无货源、虚假供给、异常转单记录，以及供应链来源、备货和履约证据是否可验证。
- **达标标准**：无重大无货源风险，且供应链可验证；具体风险分级和观察规则按配置执行。
- **对应权益**：保留成长资格和基础资源。
- **等级跃迁**：作为综合能力评分的风险门槛；红线或严重违规直接进入整改/清退判断，不以总分掩盖。

### 4.2 企划匹配供给

- **义务项**：按企划方向提供满足平台坑位的商品。
- **考核内容**：坑位商品满足情况，以及与 S/A/B 企划方向的匹配程度。
- **达标标准**：阈值按企划和商家等级配置；其中 S/A 企划匹配覆盖度 **≥80%** 为已确认口径。
- **对应权益**：提升坑位上新数、企划优先报名和资源位。
- **等级跃迁**：持续高匹配供给支持升级；未达配置要求时维持或降级，并可减少相关坑位。

### 4.3 商品发货质量

- **义务项**：持续提供质量、信息和合规均可审核的商品。
- **考核内容**：商品质量、信息完整度、合规性和审核通过率。
- **达标标准**：质量、完整度和审核通过率均达到相应层级配置目标。
- **对应权益**：商品入池推荐、月上新坑位增加、重点供应商候选和完整经营看板。
- **等级跃迁**：持续达标支持升级；未达标进入整改并影响维持或降级判断。

### 4.4 稳定供应链

- **义务项**：保证货源稳定、可补货并持续供货。
- **考核内容**：货源稳定性、补货能力和供货持续性。
- **达标标准**：缺货率、补货时效、供货波动和准确率均达到对应层级配置目标。
- **对应权益**：随供给可靠性增加相应资源和坑位配置。
- **等级跃迁**：可靠性持续提升支持升级；供应波动或未达标影响维持/降级及资源收缩。

### 4.5 版房与打样

- **义务项**：提供快速打样、趋势响应和共创开发能力。
- **考核内容**：打样周期、打样成功率和趋势/共创需求响应时效。
- **达标标准**：打样周期、成功率和响应时效达到对应层级配置目标。
- **对应权益**：优先承接趋势/共创企划，并扩展相应坑位。
- **等级跃迁**：连续达标支持升级；能力不足则影响维持/降级和企划承接范围。

### 4.6 月度坑位履约

- **义务项**：按月完成平台分配的上新坑位并稳定兑现。
- **考核内容**：当月坑位完成情况，以及连续月份的稳定兑现情况。
- **达标标准**：每月坑位达标且持续稳定；S/A 企划匹配覆盖度 **≥80%** 仍按已确认口径执行。
- **对应权益**：保持或增加坑位；未达标时减少坑位。
- **等级跃迁**：稳定履约支持升级；单月或持续未履约影响维持/降级。

### 4.7 经营动销

- **义务项**：形成真实成交并保持持续动销。
- **考核内容**：动销率、GMV 和转化率。
- **达标标准**：动销率、GMV 和转化率达到等级、类目和企划配置目标。
- **对应权益**：更多经营资源、入池推荐和增长机会。
- **等级跃迁**：持续动销达标支持升级；低于配置目标影响维持/降级及增长资源分配。

### 4.8 核价配合

- **义务项**：提供合理报价并配合平台核价。
- **考核内容**：报价合理性、接受核价结果以及虚高报价的压缩和处理。
- **达标标准**：报价合理、接受核价结果，虚高报价已按规则处理。
- **对应权益**：保留或扩大商品入池与资源资格；拒不配合时限制相应权益。
- **等级跃迁**：配合达标支持维持或升级；拒不配合或反复虚高影响降级判断。

### 4.9 品质监控

- **义务项**：持续控制问题订单并配合商品与大仓质检。
- **考核内容**：只使用 **问题订单率 = 问题订单 / 同期有效订单**，同时记录商品质检通过率和大仓质检通过率；不得使用“稳定率”。
- **达标标准**：问题订单率不恶化或按周期改善，且商品质检通过率和大仓质检通过率达到对应配置目标。
- **对应权益**：质量型资源和稳定等级资格。
- **等级跃迁**：问题订单率上升触发预警和人工复核；预警/整改未恢复时影响评分与升级、维持或降级判断。

不得将上述月度综合能力评分或等级跃迁写成“月签”。所有权益变更必须保留规则版本、观察周期、评分和审批证据。

## 5. 清退与整改边界

以下情形必须提交清退复核：严重发货异常、无货源、虚假供给、严重违规等红线；或缺货、退货、售后持续异常；或长期不达标且多次整改无效。命中经人工确认的清退规则后，商家退出托管池及相关权益。

整改期间仍应保留原始评分、问题订单和证据，不得以补录覆盖历史。只有一次独立、证据齐全的复核可以改变待处理状态；它不追溯改写既有月度结果。外部商家工作台、验厂机构、买手分配、权益系统、处罚及真实通知渠道尚未接入时，SkillTask 只保存受控人工审核和证据引用，不能冒充已完成外部动作。

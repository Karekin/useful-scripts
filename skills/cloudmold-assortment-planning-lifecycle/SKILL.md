# CloudMold AI 商品企划闭环

该 Skill 定义 Fashion88 选品经理、买手和招商协同的 AI 商品企划主流程，不是单点查询或技术巡检。目标是把经授权的淘系、小红书、抖音及商家信号转为结构化、可执行、可分发的企划画像，并将企划精准匹配给存量商家、买手和新商寻源动作。

## 总体闭环

1. **智能建策**：多源信号召回、模型训练、企划创建与挂载、清洗淘汰，形成合格 AI 企划。
2. **企划下发**：合格企划进入企划广场，并行走老商迁移、买手承接和招商寻源三条路径。
3. **结果回流**：承接、货盘、上市和经营结果回流，迭代爆款元素、企划风格和匹配模型；定期清洗企划库。

AI 是趋势雷达、机会排序和风险约束工具，不是审美或爆款的确定性裁判。AI 输出必须保留依据和不确定性；最终的风格选择、资源下注与审批仍由业务责任人完成。

## 第一层：智能建策

### 阶段一：多路数据创建 AI 企划备选池

以全网爆款和趋势信号作为企划的原始素材，确保每个候选均有来源和市场依据。

| 信号路径 | 信号源 | 输入口径与用途 |
| --- | --- | --- |
| 同款池召回 | 淘系类目搜索词 | 类目、搜索词、搜索量；反映站内需求。 |
| 同款池召回 | 小红书趋势词 | 趋势词、增速；捕捉内容侧种草趋势。 |
| 同款池召回 | 淘系爆款 | 商品标识、销量或 GMV；提供站内成交验证。 |
| 同款池召回 | 抖音爆款 | 商品、直播销量与占位；提供内容电商侧验证。 |
| 淘系机会补充 | 商家主动提报 + 派利淘图搜 | 商家先提报货盘，再以图搜做定向同款/相似款召回；不得做无目标的盲目搜索。 |
| 淘系机会补充 | 行业叶子类目爆品元素 | 下钻叶子类目，提取爆品共性元素，补充货盘机会。 |
| 市场趋势洞察 | 小红书定向账号笔记挖掘 | 锁定标杆或趋势账号，提取笔记中的风格与元素信号。 |
| 市场趋势洞察 | 抖音定向账号直播间切片 | 提取热卖货品与话术元素，补充前瞻趋势。 |

三条路径的候选必须按商品、风格、时间窗和来源证据去重合并，形成可追溯的 AI 企划备选池。

### 阶段二：模型训练

阶段一备选池进入两类互补训练，形成 Fashion88 自有的企划风格与商品判断能力。

| 训练方向 | 训练内容 | 产出与用途 |
| --- | --- | --- |
| 企划爆款元素训练 | 对召回素材中的爆款共性做特征训练。 | 沉淀版型、面料、卖点、价格带等可量化的爆款元素库，用于识别可复制机会。 |
| 企划风格训练 | 对内容侧的风格信号做训练。 | 沉淀风格分类、风格趋势权重等模型，用于企划风格定位及企划、货盘、商家、买手的匹配。 |

每次模型输出至少应说明适用类目、元素匹配、风格匹配、趋势权重、置信度和模型版本；未达到质量门槛的结果不得自动创建或发布企划。

### 阶段三：企划创建与结构化挂载

为每条企划建立可匹配、可分发、可引用的结构化画像。完整挂载是进入企划广场的前置条件，也为选品模型和商品潜爆分值计算提供统一输入。

| 挂载字段 | 含义 | 主要用途 |
| --- | --- | --- |
| 类目与风格 | 企划的类目归属与风格定位。 | 匹配商家及大店经营范围和目标风格。 |
| 精准画像 | 目标消费者的精准画像。 | 指导商家寻源。 |
| 市场空间 | 近 7 天单量与 GMV。 | 评估企划市场价值与机会空间。 |
| 淘系关联热卖商品清单 | 站内相关热卖商品集合。 | 进行竞争性对比。 |
| 建议提报价 | 建议报价与目标价格带。 | 指导商家定价。 |
| S/A/B 分层 | 企划的优先级与价值分级。 | 决定资源分配，并与既定打包率口径结合。 |
| 季节属性 | 商品的季节归属。 | 指导上新节奏和库存规划。 |
| 上市月份 | 建议首次上市时间。 | 用于排期和备货。 |
| 热销月份 | 预计销售高峰时间。 | 用于营销与流量节奏。 |
| 下市月份 | 建议退市时间。 | 用于清仓和生命周期管理。 |

每条企划还必须保留信号来源、数据时间、模型版本、评分依据、责任人和操作记录，以支持解释、审计和复盘。

### 阶段四：企划数据清洗与淘汰

按市场空间、增长趋势、季节属性、企划重复度和模型置信度定期清理企划。低价值、过期、高度重复、无法承接或证据不足的企划不得下发；可保留为观察对象，但必须标明原因、复查时间和退出条件。

## 第二层：企划下发

所有合格企划通过**企划广场**统一下发。企划广场展示已发布企划、目标店铺画像、风格要求、S/A/B 分层、目标货盘、报名条件、责任人和时限；它是下列三条路径的唯一入口。

### 路径 A：老商迁移

目标是将企划精准推送给适配的存量老商，引导其报名承接。商家匹配模型基于商家、目标店铺、竞品店铺、风格和企划特征计算适配度，并结合历史经营结果持续训练。

老商报名成功后，应绑定承接企划、目标货盘、完成时限和结果回传规则；不能承接或超时的企划进入买手承接、招商寻源或淘汰队列。

### 路径 B：买手匹配与企划竞选池

目标不是重复向买手推荐企划，而是将“市场机会明确、但直接承接不足或需要重点培育”的企划交给有能力、有容量、有渠道资源的买手主动组织供给。

企划竞选池从企划库筛选重点企划，按买手的类目专长、风格资源、历史承接表现、可用容量和分发能力进行推荐。买手认领后负责带动商家报名、组货或补足供给，并回传承接结果。未被认领或认领后无成效的企划进入招商寻源或清洗淘汰队列。

### 路径 C：招商寻源

目标是以企划为锚点，对外寻源新货盘和新商家，补齐存量供给缺口。招商应依据企划风格、S/A/B 分层、目标店铺和目标货盘定向寻找可供给的新商；新商入驻后回到企划广场完成企划承接，不能形成独立且割裂的招商流程。

## 运行规则与治理

### 企划状态机

`备选 → 训练完成 → 待创建 → 待审核 → 已发布 → 下发中 → 已承接 → 执行中 → 已关闭`

企划也可因证据不足、审核拒绝、季节过期、重复、无人承接或执行失败进入`已淘汰`。每次状态迁移必须保留责任人、时间、依据、版本和下一步。

### 发布、责任和冲突处理

- 企划发布前必须满足完整挂载、市场空间、增长、季节适配、重复度和质量门槛；高优先级企划按既定权限进入独立人工审核。
- 每条企划必须有负责人、商家报名时限、买手认领时限和招商寻源时限；超时后按规则转派、降级或淘汰。
- 老商迁移优先处理可直接承接的供给；买手竞选池处理需要主动组织的供给；招商寻源补齐其余缺口。相同商家、买手和货盘的竞争、重复触达与冲突必须在企划广场中可见并受控。

### 反馈、指标与数据边界

下发侧的商家报名、买手认领和承接、招商寻源、货盘覆盖、上市及经营结果必须回流。至少持续观察企划发布率、商家报名率、买手认领率、招商补齐率、货盘覆盖率、上市率、售罄率、毛利率和退货率，并将每项结果明确归因至爆款元素模型、风格模型或商家/买手匹配模型的迭代。

外部平台信号必须具有合法授权、明确使用范围、来源记录和更新频率。数据不足、数据过期或来源不可验证时，系统应降低置信度或停止自动下发，而非伪造市场依据。

## 自动运行

AI 运营控制台每天由 Temporal Schedule 触发。测试环境输入按 occurrence 生成新的
`waveId`、候选池、证据摘要和日历/交接引用；同一 occurrence 重试保持幂等，不会重复建波段，
不同 occurrence 不会反复处理同一组候选。

## 风险边界

- 风险等级为 R3；批准凭证只能由审批子流程注入，输入不得自带有效批准证据。
- Catalog 只拥有选品企划事实，不写渠道价格、库存或刊登。
- 毛利、退货率或企划质量不达标的候选必须失败关闭，不能为了凑款数降低约束。
- 所有状态变化必须保留幂等操作、版本历史和事务 Outbox。
- 本 Skill 描述目标业务 SOP；任何尚未接入的外部信号、模型能力或企划广场动作，必须如实展示为待建设能力，不得假称已在线运行。

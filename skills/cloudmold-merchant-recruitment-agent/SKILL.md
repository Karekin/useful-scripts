# 招商 Agent：商家线索至买手对接 SOP

本 Skill 规范 Fashion88 招商 Agent 的四段流程：**线索挖掘、商家建联、商机转化、入驻引导**。目标是以 CRM 为唯一过程记录，提升线索质量、建联效率、商机转化和买手对接效率；它不是自动准入、自动承诺或规避第三方平台限制的工具。

当前 CloudMold 尚未注册招商 CRM、企微、千牛、外呼或 RPA 的可执行能力。本 Skill 因此是受控的业务与产品规范：任何实际写入、触达、拉群、外呼、短信、入驻提交或买手交接，都必须在已授权的系统能力、账号权限、频次限制和审计机制落地后执行。商家正式 KYC、合同、法定准入、激活和权威状态回读仍由 `cloudmold-merchant-onboarding-lifecycle` 负责；托管商家后续验厂、试用期与成长运营由 `cloudmold-merchant-managed-growth-lifecycle` 负责。

## 0. 通用控制面

### 0.1 责任边界

- **招商小二/BD**：确认线索分配、处理升级问题、作出受授权的商业沟通与例外决定，并对关键承诺负责。
- **招商 Agent**：归集与评分线索、生成建议、输出已批准的话术、结构化招商小记、识别意向与阻塞、编排提醒和升级。
- **RPA**：只执行已获授权、可审计、可停止的低风险界面操作，并把结果回写 CRM；不得绕过 API 限流、平台规则、权限控制或账号安全措施。
- **CRM**：招商过程的唯一事实记录，保存来源、评分、分配、触达、对话摘要、状态、下一步、责任人和证据引用。
- **权威审核/买手系统**：分别对正式准入结论和买手接收结论负责。AI 不能伪造或替代这些结论。

### 0.2 通用状态与留痕

每条线索至少保存：唯一商家/店铺标识、来源与导入批次、数据授权范围、招商画像标签、综合与分项评分及模型版本、负责人、当前状态、下一步动作与截止时间、触达/沟通摘要、人工修改原因和证据引用。

标准状态：`待校验`、`待分配`、`待建联`、`建联中`、`待资格判定`、`已入群`、`答疑中`、`有意向`、`入驻引导中`、`待买手接收`、`已交接`、`淘汰`、`免打扰`。任何淘汰、免打扰、正式准入或买手接收均须记录规则、原因、责任人与时间。

触达前必须检查数据来源与授权、渠道规则、触达频控、静默时段、既有拒绝/投诉/免打扰记录。商家拒绝、投诉或进入免打扰后，立即停止自动触达并转人工处置。

## 1. 线索挖掘

### 1.1 线索引入

淘宝服饰货盘商家按招商画像、在线商品、商家经营信息和商品企划匹配度进行多重过滤、分层分类后入 CRM。站外线索仅在来源合法、用途授权、字段完整、准确度满足阈值且已去重后，按批次入 CRM。

AI 构建招商商家知识库，支持业务自定义招商画像、Agent 圈商和目标清单输出。它必须标记每项数据的来源、采集时间、可信度和缺失项；不得把未经确认的推断当作商家事实。

### 1.2 线索评分

对线索进行 360 度评估，至少覆盖：供应链质量、上新实力、爆款潜力、企划匹配度、速度赛能力和履约能力。CRM 同时展示综合分、分项分、推荐理由、风险/缺失提示、模型版本及评分时间，并支持按分项排序。

评分模型的每个维度必须有明确的数据来源、口径、权重、缺失处理和失效策略。AI 推荐只作决策辅助；招商小二可调整排序或拒绝推荐，但必须留存原因，用于后续模型校准。

### 1.3 线索交付

线索卡至少包含渠道、商家或店铺名称、AI 评分、推荐理由、基本经营情况、建议优先级、建议触达方式、风险提示和 CRM 负责人。Dashboard 支持筛选、分配、画像查看、招商小记和漏斗监控，并使入库数量可按业务节奏调控。

## 2. 商家建联

### 2.1 线索分配与跟进策略

基于线索画像与历史招商成功特征，预测转化概率和转化时效，为招商小二或 Agent 单元提供个性化分配建议。分配不得只追求最高预测转化率，还必须考虑负责人容量、在跟数量、类目经验、响应时效和必要的探索配额，防止模型把优质线索长期集中给少数人员。

业务确认分配后，Agent 输出跟进节奏、触达方式、已批准话术、拜访预案和下一步动作；实时分析进度和效率，对停滞、逾期或异常触发提醒和人工升级。

### 2.2 自动建联

高分线索可在已授权的渠道中建联：千牛布点并展示招商小二或商家群二维码；获授权的站外平台触达；CRM 中已授权联系方式的企业微信好友申请；以及合规的电话/外呼和短信引导。企业微信好友申请当前业务上限为**每日 20 人**，实际执行以平台和组织当期规则中更严格者为准。

RPA 只执行受管控账号、白名单动作和批准的话术。它要回写成功、拒绝、无响应、失败原因和下一步动作；失败只能在既定次数与间隔内尝试备用渠道，不能借由模拟人工绕过限流。电话、短信和站外触达必须有联系方式来源、授权、退订/免打扰机制与审计记录。

### 2.3 资格判定

资格判定首先校验不可突破的硬规则，再结合建联结果、结构化招商小记、货盘和经营特征，由 AI 输出潜力、风险和待补信息建议。模型输入、置信度、依据和版本必须可回看；低置信度、规则冲突或高风险线索自动转人工复核。AI 不单独作出正式准入结论。

### 2.4 商家入群

在资格通过、身份与联系人确认、商家同意入群、群类型匹配且无免打扰/投诉风险后，可由已授权 RPA 邀请商家加入 Fashion88 商家群，并同步添加群聊机器人。群内必须具备规范群名、招商小二、机器人和商家等必要成员。

机器人可进行欢迎、任务提醒、已批准的信息播报和群激活；系统持续监控成员完整性、活跃度、对话频次和响应时效。低活跃、无人响应、成员缺失、投诉或敏感问题应触发明确的提醒、人工介入、暂停触达或退出群流程。

## 3. 商机转化

### 3.1 群聊全托管

Fashion88 商家群由机器人账号承接已批准知识库内的日常答疑和客服接待。无法回答、涉及价格/权益/准入承诺、投诉争议或低置信度的问题，机器人须通过钉钉等已授权渠道请求人工，并跟踪响应时效；超时按升级策略预警。

RPA 可在授权范围内执行群内日常信息播报和入驻任务提醒。群聊自动化必须遵守频控、静默时段、免打扰、人工接管和可撤回/停止机制。

### 3.2 商家档案管理与招商小记 Agent

招商小记 Agent 以原始沟通记录为输入，输出结构化招商小记：沟通时间、参与人、意图阶段、关键问题、承诺边界、商家需求、资料缺口、风险、下一步动作、责任人和截止时间。原始记录与摘要必须关联，便于人工核验和纠错。

系统基于群聊记录、CRM 已有信息及已授权外部数据，抽取、补全并更新商家档案，标记来源和可信度。对缺失、冲突、失效或无法确认的关键字段，向商家推送补充链接；超时未补时提醒并转招商小二跟进。不得猜测、代填或覆盖商家已确认的事实。

### 3.3 商机判断与 BD 策略

基于结构化招商小记和群聊对话记录，识别商家入驻意向、意向阶段、置信度、判断依据和阻塞因素。至少区分：无响应、资料待补、初步了解、明确有意向、暂缓、无意向和免打扰。低置信度必须转人工。

Agent 可按意向匹配**已批准**的 BD 沟通策略，如暖群、答疑、价值推荐、任务提醒和人工介入建议；不得自行承诺价格、权益、准入结果或采取误导、施压式沟通。明确有意向且满足前置条件的商家进入入驻引导。

## 4. 入驻引导

### 4.1 辅助填写入驻信息

基于实时入驻状态，向商家推送分阶段任务提醒与差异化引导。仅在商家明确授予字段级操作授权时，Agent 才可协助预填、校验和采纳提醒；每项预填值必须展示来源、可编辑且由商家最终确认。缺失、冲突或未验证信息不得猜测或代填。

### 4.2 辅助商家入驻审核

系统识别任意操作场景中的页面/系统错误、字段校验失败、资料缺失、资质不符、长期停滞和审核驳回等异常，输出定位说明、材料清单、自检反馈、规则培训和人工支持建议。AI 只帮助商家理解规则并修正可验证的问题；权威审核系统或有权人员作出审核结论，AI 不得承诺通过。

### 4.3 辅助商家提交货盘

Agent 根据招商货盘标准和商家已授权信息，辅助生成货盘准备清单、字段映射、完整性/合规预检和问题修复建议。商品、价格、图片、资质及其他商家事实必须由商家确认后提交；异常、缺失或高风险内容转人工处理。

### 4.4 对接买手

只有当正式入驻审核通过、货盘满足招商门槛、商家身份有效，并且买手承接范围和容量匹配时，才可邀请买手小二入群。交接必须生成可回看的摘要：商家画像、企划匹配、货盘状态、已完成事项、未解决风险、下一步与责任人。买手接收确认后进入 `已交接`。

## 5. 经营指标与验收

每周默认目标漏斗为：约 **1,300** 条入库线索 → **10%** 有效建联/资格通过（约 **130** 个）→ **50%** 商机转化并完成买手对接（约 **65** 个）。实际统计必须分别定义分子、分母、观察窗口、去重规则和归因规则，不得把预测分数当作实际转化。

至少监控：线索数据完整率和新鲜度、评分可解释率、分配接受率、建联成功率、有效联系人率、资格通过率、入群率、首次响应和人工升级时效、意向率、货盘一次通过率、各节点停留时长、买手接收率、投诉/退订率与人工介入率。

交付验收要求：CRM 可完整回看商家全生命周期；线索卡、招商小记、评分与策略建议均可解释且可纠错；群名与成员规范；所有自动操作可审计、可停止、可回写；商家同时满足招商和买手双节点的入驻要求后，才可视为完成入驻与交接。

## 6. 非协商限制

- 不得使用站外采购线索或联系方式进行超出授权范围的触达。
- 不得用 RPA 绕过第三方平台的 API 限流、权限、风控或账号安全规则。
- 不得由 AI 单独作出淘汰、免打扰、资格通过、正式准入、审核通过或买手接收结论。
- 不得伪造商家事实、沟通记录、审核证据或货盘内容。
- 不得在商家拒绝、投诉或免打扰后继续自动触达。

## 7. 默认实现蓝图

本节给出尚未具备真实系统集成时的默认实现。它规定服务边界、输入、输出和失败回退；接入 CRM、企微、千牛、外呼或 RPA 后，应以同名能力替换模拟适配器，不改变业务状态机与审计字段。

### 7.1 共同基础

- **CRM 招商工作台**：保存线索卡、状态机、分配、招商小记、待办、触达审计、群关系和买手交接；所有外部动作先写 `待执行`，得到回执后才写最终结果。
- **招商知识库**：以已批准的招商政策、入驻规范、货盘规范、FAQ 和话术为来源，按版本、适用类目、有效期和审批人管理；检索不到或低置信度时直接转人工。
- **Agent 编排器**：按线索状态触发评分、策略、摘要、提醒和升级任务，输出结构化建议而非直接改变高风险业务结论。
- **RPA 适配器**：统一接收白名单动作、受管控账号、幂等键、频控策略和审计上下文；默认拒绝未知平台、未知账号和超频请求。
- **人工工作队列**：承接低置信度、规则冲突、敏感承诺、投诉、异常审核和超时任务；记录受理人、服务等级、处理结论和回写状态。

### 7.2 线索挖掘默认实现

| 模块 | 默认输入 | 默认动作 | 默认输出与回退 |
|---|---|---|---|
| 线索引入 | 淘宝服饰货盘批次或已授权站外线索批次、招商画像版本 | Schema 校验、来源/授权校验、商家与店铺去重、画像标签匹配、缺失字段标记 | 创建 `待校验` 线索卡；来源、授权或关键字段不合格时拒绝入库并进入数据治理队列 |
| 线索评分 | 已校验线索卡、企划、经营和供应链特征 | 计算供应链、上新、爆款、企划、速度赛和履约分项；生成综合分、推荐理由和不确定性 | 更新为 `待分配`；特征不足或模型置信度低时仅标记“待人工评分”，不参与自动推荐 |
| 线索交付 | 已评分线索、招商单元容量和类目范围 | 生成线索卡、Dashboard 筛选视图、优先级队列和建议触达策略 | 交付给可承接单元；超过容量或无匹配单元时进入待分配队列，不静默丢弃 |

### 7.3 商家建联默认实现

| 模块 | 默认输入 | 默认动作 | 默认输出与回退 |
|---|---|---|---|
| 线索分配 | 评分、画像、负责人容量、历史表现和探索配额 | 计算候选负责人排序，展示转化/时效预测与原因，等待业务确认 | 创建负责人和跟进计划；拒绝或超时未接受时重新分配或转人工主管 |
| 自动建联 | 已分配线索、授权联系人、渠道白名单和话术版本 | 选择合规优先渠道，创建幂等触达任务；企微好友申请遵守每日 20 人及更严格平台限制 | 回写成功、拒绝、无响应或失败；仅按预设次数切换备用渠道，超过阈值进入人工队列 |
| 资格判定 | 建联结果、招商小记、货盘/经营特征和硬规则 | 先做硬规则校验，再输出潜力、风险、待补项与置信度 | 高置信度仅进入“建议通过/建议补充”待人工确认；低置信度或冲突直接转人工复核 |
| 商家入群 | 已确认的资格结果、身份、入群同意、群类型和账号权限 | 创建邀请任务、添加机器人、发送欢迎与首个任务 | 回写群标识和成员状态；邀请失败、拒绝或投诉时停止自动化并转人工 |

### 7.4 商机转化默认实现

| 模块 | 默认输入 | 默认动作 | 默认输出与回退 |
|---|---|---|---|
| 群聊全托管 | 群聊消息、知识库版本、角色和敏感词规则 | 先检索已批准知识，再生成答复；定时播报已批准内容和任务提醒 | 记录答复、依据和置信度；低置信度、投诉、承诺或争议自动创建人工求助单 |
| 商家档案管理 | 原始沟通记录、CRM 已有字段和授权数据 | 招商小记 Agent 抽取意图、问题、待办、风险和档案字段变更 | 生成可编辑招商小记并附原始记录引用；冲突或不确定字段标记待确认并推送补充链接 |
| 商机判断 | 招商小记、群聊意图、任务完成度和触达历史 | 输出意向阶段、置信度、阻塞原因和已批准 BD 策略 | 更新建议状态与下一步；明确拒绝、投诉或免打扰立即停止触达，低置信度转人工 |

### 7.5 入驻引导默认实现

| 模块 | 默认输入 | 默认动作 | 默认输出与回退 |
|---|---|---|---|
| 辅助填写入驻信息 | 入驻状态、商家授权字段、已有档案和表单规则 | 生成分阶段待办、预填建议、校验提示与提醒计划 | 商家确认后才提交；无授权、字段冲突或校验失败时只给出问题清单并转人工支持 |

### 7.6 默认可观测性

默认每个任务关联线索 ID、商家/店铺引用、来源批次、模型/知识库/话术版本、负责人、幂等键、触发时间、执行结果和人工修改。Dashboard 以周为单位展示 1,300 → 130 → 65 漏斗及分渠道、分画像、分负责人、分策略的实际转化，不以预测分数替代真实结果。
